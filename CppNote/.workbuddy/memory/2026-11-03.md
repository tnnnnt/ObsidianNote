## ★ 重大更正：真正的元凶是 types.json（推翻上面的复选框方案）
- 排查发现 `.obsidian/types.json` 才是 Obsidian 1.14.5 属性类型的**权威文件**（`{"types": {"掌握程度": "text"}}`），它把类型钉死为 text，导致之前对 `app.json` 的所有修改全被覆盖——所以怎么配都出不来下拉。**与「安装损坏」无关，是配置文件选错了。**
- 修法：把 `types.json` 的 `"掌握程度"` 从 `"text"` 改成 `"select"`；同时在 `app.json` 的 `properties.掌握程度` 写入 `type:select` + 5 个选项（未学/会看/会写/熟练/精通）。
- 已用脚本 `_to_select.py` 把 60 篇从「5 个复选框」回退为单值 `掌握程度: 未学`（全部未学，无损）。
- 同步更新 `学习看板.md` 的 Dataview 查询为单值 `掌握程度`（原复选框查询已失效），`C++.md` 说明改为「下拉字段」。
- 复检：types.json=select、app.json 选项 5 个、60 篇单值字段齐全无残留复选框、0 断链。
- **经验**：以后改 Obsidian 属性类型，先改 `.obsidian/types.json`（type 映射），选项再配 `app.json` 的 properties；不要只改 app.json。用户需「托盘 Quit 彻底退出」再重开才会重读 types.json。
- **结果更新**：types.json 设为 "select" 后，属性变成**「改不动/无法编辑」的坏控件**（用户反馈「掌握程度编辑不了了」）。结合此前类型菜单缺「选择」→ 判定：**该安装对 Select 支持不完整/有 bug**。已把 types.json 回退为 `"text"`、app.json properties 清空，恢复可编辑文本状态（60 篇字段未动，仍单值）。
- **结论**：不要再用「手改 types.json/app.json 硬设 select」的办法（此构建会渲染成坏控件）。真要下拉，让 Obsidian 自己写配置：命令面板 → Show all properties（显示所有属性）→ 右键属性 → 属性类型 → 选「选择」；或直接重装 Obsidian（About 页本就提示需重装）。
- **最终落地（2026-11-03 深夜）**：用户拍板「恢复 5 个复选框」。已把 60 篇从单值 `掌握程度` 改回 5 个复选框（全部 未学 → 仅 `未学:true`），清掉 types.json 里残留的 `掌握程度` 键（现仅剩 aliases/cssclasses/tags），`学习看板.md` 查询与 `C++.md` 说明同步改回复选框版。复检：0 缺字段 / 0 残留 / 0 断链。**此为当前定稿方案**（原生下拉在此安装不可用，除非重装）。
